# LogHub-2.0 baseline table

Generated by `julia --project benchmarks/loghub2/sweep.jl` against the
2k-line annotated subsets fetched by `download.jl`. One row per
`(dataset, parser)` pair; metrics in percent (PA, GA, FGA, FTA, NMI,
ARI, Purity, V-measure).

All six baseline parsers are wired in `run.jl`:

- `identity`  — every line is its own template (PA/GA floor).
- `constant`  — one global `<*>` template (template-count floor).
- `num_mask`  — `\d+ → <NUM>` plus literal-equality clustering.
- `mask`      — the full typed-slot battery in `src/PreProc/Masking.jl`.
- `drain`     — Drain3 port in `src/Parsers/Drain.jl`.
- `mask+drain`— typed-slot masking feeding Drain.

## Notes

- **Drain matches published numbers** on HDFS (NMI 99.92, GA 99.75)
  and OpenSSH (NMI 99.85, GA 78.75). Apache_2k is small enough that
  `num_mask` already saturates every clustering metric.
- **PA (exact-template match) is 0 for `mask+drain`** because our
  typed-slot placeholders (`<IP>`, `<INT>`, `<DECIMAL_EN>`, …) are
  more specific than LogHub's single `<*>` placeholder. Drain's raw
  output gets 46–69% PA on datasets where its generalisation
  happens to match the ground-truth masking.
- The `mask` and `mask+drain` rows currently take ~11 s per
  dataset — the Rust `parse_line` is called once per line through
  the FFI boundary. A batched FFI API would amortise the crossing
  cost across an order of magnitude.
